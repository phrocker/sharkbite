03 / THE ENGINE

One engine.
Embedded or clustered.

Sharkbite stores its own data. The Shoal engine is a sorted key/value store with a WAL, flush, and compaction. It runs in-process with no cluster, or as serving roles when you need them, with RFile or Parquet tablets on local disk or object storage.

Embedded, zero dependencies

shoal-embed runs standalone. No ZooKeeper, no coordinator, no external process. Splits, flush, and compaction are built in. Point it at a directory or a bucket.

go run ./cmd/shoal-embed init \
  --table graph --data ~/.shoal/data
go run ./cmd/shoal-embed write \
  --table graph --data ~/.shoal/data < mutations.jsonl

Query the shape of your data

ShoalQL with predicates, ranges, ordering, and aggregation. Graph traversal and latent-edge discovery. Document and term-index predicates. Exact vector search, with a distributed IVF-PQ index for scale. One EXPLAIN shows the plan.

Already on Accumulo? Bring it along.

Byte-compatible RFiles, an Accumulo 4 client in Go, a stable C ABI, and a Python binding over that ABI (import sharkbite or import pysharkbite). Scan server, tablet server, and compactor roles speak Accumulo-native protocols. Status per role is in FEATURES.md.
